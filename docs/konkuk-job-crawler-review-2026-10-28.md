# 건국대 진로취업센터 외부행사 게시판 크롤링 검토

검토일: 2026-10-28 (KST)

## 결론

**목록에서 게시글 상세로 들어가는 크롤링이 가능하다.** 사용자 Chrome에서 목록·상세·다음 페이지를 직접 확인했고, 새 AWS 계정의 서울 리전 CloudShell에서도 로그인 쿠키 없이 목록 및 상세 HTML을 받았다.

기존 AWS 계정 로그인은 필요하지 않다. 이번 검증은 새 계정 UPNCOL에서 수행했다. 기존 봇을 이전하는 작업이 아니라 독립된 수집기를 만드는 경우 새 계정으로 구성하면 된다.

이번 작업은 접근성 및 데이터 구조 검토다. 운영 크롤러 배포, 정기 실행 설정, 서비스 DB 등록, OCR 실행은 아직 하지 않았다. CloudShell 성공은 해당 실행 환경에서의 접근 확인이며, 최종 배포 환경에서도 연결 검증이 필요하다.

상단 공지와 일반 목록에 같은 게시글 `1210895`가 함께 나타났다. 목록 순번이나 제목으로 저장하지 않고 `(source, boardId, articleId)`에 유일성을 부여해야 한다. 첫 페이지 HTML에서는 중복을 제외한 상세 링크 17개가 검출되었다.

## 2. 새 AWS 계정에서의 HTTP 검증

서울 리전 CloudShell에서 STS로 로그인 계정을 검증한 뒤, Python 표준 HTTP 클라이언트로 아래 공개 주소를 조회했다. 사이트 로그인·브라우저 쿠키를 사용하지 않았으며, 요청 사이에 2초 간격을 두었다.

| 대상 | 결과 | 확인 내용 |
| --- | --- | --- |
| `/robots.txt` | HTTP 200, 32 bytes | `User-agent: *`, `Disallow: /*/*Mngr` |
| `/bbs/job/4084/artclList.do` | HTTP 200, 44,290 bytes | HTML, 고유 상세 링크 17개 |
| `/bbs/job/4084/1210925/artclView.do` | HTTP 200, 9,358 bytes | HTML, 본문 영역 `view-con` 존재 |

웹 검색 도구에서는 웹방화벽 차단 페이지가 반환되었지만, 사용자 브라우저와 위 AWS 요청에서는 정상 페이지를 확인했다. 따라서 검색 도구의 결과만으로 수집 불가라고 판단하면 안 된다. 운영 시에는 HTTP 200이어도 차단 문구 또는 본문 구조 누락을 확인하여 실패로 처리해야 한다.

robots.txt에서 이번 공개 게시판 경로에 해당하는 금지 규칙은 확인되지 않았다. 이는 콘텐츠 재배포 허가를 의미하지 않는다.

## 4. 추출 및 갱신 규칙 제안

1. 목록 전체 페이지에서 상세 주소를 모으고 게시글 ID로 중복을 제거한다.
2. 각 상세의 `.view-title`, `.view-con`, 작성자·등록일 영역, 첨부 및 외부 링크를 수집한다. 제목의 `새글` 표시는 제거한다.
3. 원문 주소, 수집 시각, 원문 HTML 또는 정제 텍스트, 이미지·첨부 URL, 원문 해시를 함께 보관한다.
4. 기존 게시글도 다시 읽는다. 조회수·화면 장식·공백 차이는 제외한 내용 해시가 달라지면 동일 레코드의 새 버전으로 저장한다.
5. 이미지·첨부는 URL이 같아도 파일이 바뀔 수 있다. 파일 해시 또는 검증 가능한 HTTP 변경 정보를 사용하여 변경을 감지한다.
6. 모집 마감일·행사일·교육기간·발표일을 구분한다. 날짜가 없으면 미확정으로 남기고, 포스터 중심 글은 OCR/이미지 해석 이후 검수한다.
7. 목록에서 사라졌다는 이유만으로 모집 종료·삭제 처리하지 않는다. 일시 실패, 페이지 이동, 실제 삭제를 구분한다.
8. 주최기관과 게시글 작성자를 구분한다. `진로취업센터`는 게시자이며 항상 행사 주최자가 되는 것은 아니다.
9. 이 게시판에는 채용 안내도 섞여 있으므로 전부 대외활동으로 자동 분류하지 않는다.
10. 초기에는 검수 대기 데이터로 수집하고 서비스 게시 여부를 별도로 관리한다. 사람이 수정한 필드는 후속 수집으로 무조건 덮어쓰지 않는다.

외부 링크는 우선 주소를 수집한다. 연결된 모든 외부 사이트를 무제한으로 따라가는 기능은 별도 범위로 다룬다. 원문 HTML을 서비스에서 그대로 실행하지 않고 정제하며, 이미지·첨부 다운로드에는 허용 호스트·크기·파일 형식 제한을 둔다.

## 5. CamNecT 연동 시 주의점

현재 `ExternalActivity` 모델에는 제목, 주최기관, 대상, 신청 시작·종료일, 발표일, 공식 URL, 본문, 썸네일 키가 있다.

- `applyEndDate`는 `LocalDate`이므로 위 경진대회의 **18:00 마감**을 표현할 수 없다. 수집 원본에는 시각과 시간대까지 보존하고, 서비스에 정확한 마감 판정이 필요하면 모델/API 확장을 검토해야 한다.
- 원문 게시글 ID, 수집 이력, 원문 변경 여부, 추출 확신도, 검수 상태를 별도 수집 테이블에 둔다.
- `thumbnailKey`에는 외부 이미지 URL을 그대로 넣지 않는다. 기존 파일 저장·제공 방식에 맞춰 연결한다.
- 원문 URL과 실제 신청/주최기관 URL을 구분하여 보관한다.

관련 코드: `src/main/java/CamNecT/server/domain/activity/model/external_activity/ExternalActivity.java`.

## 6. 새 AWS 구성안과 다음 구현 단계

구성 제안: **정기 실행 → 목록/상세 HTTP 수집 → 원문 및 변경 이력 저장 → 필요한 글만 이미지/첨부 분석 → 검수 후 서비스 반영**.

현재 표본은 브라우저 렌더링 없이 HTML로 접근 가능하므로 HTTP 파서를 우선 구현한다. 정기 실행 수집기를 Lambda와 EventBridge Scheduler로 구성하고 원문 보관과 처리 상태 저장을 분리하는 방안을 검토할 수 있다. 이미지 분석 작업량과 실제 실행 시간을 확인한 후 실행 환경을 확정한다.

초기 운영값 제안은 6시간 주기, 동시 요청 1개, 요청 간 2~3초 간격이다. 재시도에는 대기 시간을 늘리고, 403/429·차단 페이지를 받으면 해당 실행을 중단한다. 실제 운영 주기로 확정된 값은 아니다.

다음 구현 순서:

1. 목록 페이지 순회와 상세 파서를 만들고 위 3개 유형을 표본으로 검증한다.
2. 중복 방지, 기존 글 변경 감지, 실패 시 기존 데이터 유지 기능을 구현한다.
3. 모집/행사 날짜 추출 및 이미지 중심 글의 검수 분기를 구현한다.
4. 새 AWS 계정의 최종 실행 환경에서 수동 1회 실행하여 결과를 확인한다.
5. CamNecT 반영 경로와 검수 절차를 연결한 뒤 정기 실행을 활성화한다.

이번 검증만으로 49개 전체 글의 완전한 추출, 이미지 인식 정확도, 외부 신청 사이트 수집, 장기간 무차단 동작까지 보장하지는 않는다.
