# 커뮤니티 첨부 재시도: 프론트 연동 후속 PR

[서버 단독 우선 수정 PR #306](https://github.com/CamNecT/CamNecT-Server/pull/306) 다음에 머지한다. DB migration은 추가하지 않는다. 이 변경은 프론트에서 replaceFileKeys를 보내야 사용자 재시도 흐름까지 해결된다.

## API 계약

`POST /api/community/posts/uploads/presign`에 선택 필드 `replaceFileKeys`를 추가한다.

```json
{
  "items": [
    {"contentType": "image/png", "size": 12345, "originalFilename": "retry.png"}
  ],
  "replaceFileKeys": ["이전 presign 응답의 실패한 fileKey"]
}
```

- 미전송/null/빈 배열이면 기존 추가 발급 방식이다.
- 지정한 본인 소유 COMMUNITY_POST_ATTACHMENT 미사용 티켓만 만료시키고 새 티켓을 발급한다. 포트폴리오 썸네일의 원자적 교체 방식은 재사용하지만, 사용자 전체 PENDING을 만료시키지는 않는다.
- 정상 첨부의 티켓, 이미 USED인 티켓, 다른 사용자/목적은 변경하지 않는다. 새 입력 검증·한도·서명 발급 실패 시 기존 티켓 만료도 롤백된다.
- replaceFileKeys는 최대 3개다. 남은 유효 PENDING + 새 items도 최대 3개다.
- 다른 사용자/목적은 403/49310, USED는 400/49010, 존재하지 않는 키는 404/49410, 중복 키는 400/49022다. DTO 형식/길이 오류는 400/40000과 errors[]를 사용한다.
- 이미 EXPIRED인 키는 재시도를 위해 허용한다. 교체된 이전 키로는 게시글을 저장할 수 없으므로 새 응답의 fileKey/uploadUrl을 사용한다.
- S3 객체는 이 API에서 즉시 삭제하지 않는다. 이미 발급된 서명 URL은 만료 전 PUT이 가능하지만 만료된 티켓으로 게시글에 연결할 수 없다.
- 응답을 잃어 키를 모르는 티켓은 강제로 정리하지 않는다. replaceFileKeys를 보내지 않는 기존 프론트에서는 한도 초과가 계속 발생할 수 있다.

## 프론트에 넘길 문장

> 커뮤니티 첨부 업로드 실패 후 10분 동안 재시도가 막히는 문제를 해결하기 위해 presign API에 replaceFileKeys를 추가했습니다. presign 응답의 fileKey를 보관하고, 업로드 실패·취소 후 재발급할 때 폐기할 키만 replaceFileKeys 배열에 넣어 새 items와 함께 보내 주세요. 정상 업로드한 다른 파일은 교체 목록에서 제외해야 합니다. 교체가 성공하면 새 응답의 fileKey/uploadUrl을 사용하고, 게시글 저장에는 유지한 정상 파일과 새 파일 키를 함께 전달해 주세요. 이미지 디코딩·크기 검사는 가능하면 presign 전에 수행하고 저장 실패 시 입력 내용을 보존하며 버튼 상태를 복구해 주세요. 서버 배포 후 이 프론트 연동까지 확인해야 #300을 완료 처리할 수 있습니다.

## 검증과 순서

최대 한도에서 실패한 티켓만 교체, 실패 3건 전체 교체, 기존 클라이언트의 추가 발급, 소유권·목적·USED 보호, 유효하지 않은 파일·서명 실패·한도 실패 시 롤백, 교체된 키의 consume 거절을 회귀 테스트한다. S3와 인증 가드는 테스트 대역, 티켓 저장과 트랜잭션은 H2를 사용한다.

JDK 21에서 첫 PR과 이 변경을 합친 최종 브랜치의 전체 553개 테스트가 통과했다(실패·오류·건너뜀 0).

순서는 서버 단독 수정 PR → 이 서버 API PR → 프론트 연동 확인이다. 기존 기능 PR #303/#304/#305는 이후 순서이며, 선택한 기프티콘 PR은 댓글 V18 뒤로 미적용 migration 번호를 재배정해야 한다.
